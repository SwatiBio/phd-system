# Business Logic — PhD-OS

## Research domain

MAHE PhD program (3.5 years, Dr. TMA Pai). Research: lichen metabolites — isolation, characterization, molecular docking against antimicrobial targets. Computational + wetlab work.

## Log format

One line per entry, appended to the current ISO-week file (`daily/logs/YYYY-Www.md`):

```
- **HH:MM** text #tags
```

- Multi-line input collapses to one line (newlines → spaces)
- Tags: 8 curated (`experiment reading idea meeting university writing data analysis`) plus free-form
- Free-form tags auto-register in `daily/tags.md` on first use
- Day sections (`## YYYY-MM-DD`) are created as needed
- Consumers: `site/lib/logs.js`, `.github/scripts/weekly_review.py`, `logbook.html`

## Task format

```markdown
- [ ] text 📅 YYYY-MM-DD
- [ ] text 🔁 every 6 months 📅 YYYY-MM-DD
```

- Section heading must be `## Active`
- Recurring tasks (`🔁`) roll forward on tick — never close. Due date advances by the interval, clamping month ends. If the roll lands in the past, keep rolling until today or later.
- Due date emoji is `📅` — stripped for display
- Consumers: `site/lib/tasks.js`, `.github/scripts/weekly_review.py`

## Milestone grammar

Dates in `system/milestones/milestones.md` use offsets from registration, never hardcoded calendar dates:

```
**Target:** reg + 3 days
**Targets:** reg + 6 months · reg + 12 months · reg + 18 months
```

The `reg:` date in the file's YAML frontmatter is the single source. The app computes all dates from it. Changing `reg:` moves the whole timeline.

### Recurring mandates (Section 19)

- **Daily:** attendance recorded on all working days
- **Weekly:** logbook → supervisor for review/approval (the official record of guide contact)
- **Logbook must record:** tasks performed daily, status and results, pending research questions, coursework status
- **Before NOC:** full logbook submitted with the document set

### Publication requirements

- 2 first-author Scopus/WoS papers (1 review + 1 thesis original) **or** 1 first-author Q1 original — published/accepted before synopsis
- 2 conference presentations with certificates — no predatory conferences

## Tag vocabulary

Curated tags (chip shortcuts in the log form):

| Tag | Use for |
|---|---|
| `#experiment` | Wetlab or computational runs |
| `#reading` | Papers, books, articles |
| `#idea` | Research ideas, hypotheses |
| `#meeting` | Supervisor meetings, DAC, discussions |
| `#university` | Admin, coursework, registration |
| `#writing` | Paper drafts, synopsis, reports |
| `#data` | Datasets, analysis results |
| `#analysis` | Data processing, statistics |

Free-form tags are any `#word` not in the curated list. They register in `daily/tags.md` and appear in the autosuggest under "Your tags".

## Weekly review

`daily/reviews/latest.md` — generated by `.github/scripts/weekly_review.py` (Sunday 12:30 UTC). Gathers stats only (days logged, entries, tasks done/overdue, questions, ideas, rough fragments). Verdicts happen in chat with pi, not in the script.

Sections: week in numbers, what you did, what slipped, open questions, ideas, rolled-over tasks, rough pile.

## Paper digest

`research/papers/digest-latest.md` — generated by `.github/scripts/paper_digest.py` (Monday 01:00 UTC). Searches OpenAlex for topics defined in `research/papers/topics.md`. Papers from the last 8 days. The digest shows up on the dashboard if there are matches.

## Paper note structure

Every paper note (`research/papers/*.md`) must have these body sections (defined in `config.yml`, enforced by `validate-cms.py`):

```markdown
## What it did

## How

## Key result

## What it means for me

## Sparked
```

The Zotero importer (`zotero_import.py`) produces these same sections. If you change them in `config.yml`, update the importer too.
